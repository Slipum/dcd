# Идемпотентность и защита от лишних обновлений

`apply` это сходимость: желаемое состояние (политика + кандидат) сравнивается с фактическим (labels контейнера) и приводится к желаемому. Повторный запуск при совпадении ничего не меняет.

## 1. Решение по каждому сервису
```
candidate = resolve(track)  # digest манифеста платформы Docker-демона
current   = labels.dcd.digest, иначе adopt(RepoDigests)
if candidate == current                     -> NoOp
if candidate == labels.dcd.rejected         -> Skip (rejected)
if semver and version(candidate) < current  -> Skip (no downgrade)
if daemon and not stable_for elapsed        -> Wait
if approval == manual                       -> Pending
else                                        -> Update
```
Порядок проверок фиксирован. Результат зависит только от входов, без побочных эффектов.

## 2. Источники лишних обновлений и меры
| Источник | Мера |
|----------|------|
| Digest индекса (multi-arch) меняется из-за чужой платформы | Сравниваем digest манифеста платформы Docker-демона (`docker info`, не хоста; на Apple silicon это linux/arm64). Платформа может быть переопределена `platform:` в compose |
| Compose пересоздаёт контейнер из-за изменившегося конфига | Override-файл и labels детерминированы: стабильный порядок ключей, без времени, без случайных значений |
| Контейнер создан не утилитой, labels нет | `adopt`: сверка RepoDigests образа с digest индекса и манифеста кандидата; совпало — NoOp, нет — один recreate |
| Тег откатили или удалили, semver-кандидат ниже текущего | Запрет downgrade (`dcd.tag` в labels); понижение только при изменении границ в Git или явным `rollback` |
| После отката daemon снова пытается тот же плохой digest | `dcd.rejected` в labels; сброс, когда появился другой digest, или `--retry-rejected` |
| Несколько push подряд, вебхуки дублируются | События схлопываются по сервису; `stable_for` (daemon) ждёт, пока digest перестанет меняться |
| Деплой одного сервиса трогает соседей | `up -d --no-deps <service>` |
| Два процесса деплоят один стек | Блокировка на стек (FR-17) |
| Деплой оборван на середине | Повтор сходится: сравнение по labels и фактическому контейнеру, не по «журналу операций» |
| Rate limits registry | HEAD манифеста, без скачивания слоёв |

`stable_for` работает только в daemon (хранится в памяти). Явные CLI-команды его игнорируют.

## 3. Тесты (классы эквивалентности)
- candidate == current: NoOp, ноль мутирующих вызовов (проверка через mock Docker).
- candidate != current, auto: ровно один деплой.
- candidate == rejected: Skip; другой digest после rejected: Update и сброс rejected.
- Multi-arch: изменился только чужой платформенный манифест, индекс другой: NoOp.
- semver: ниже текущего: Skip; выше: Update; границы изменились в Git: Update.
- Нет labels + RepoDigests совпал: NoOp; не совпал: один Update.
- Два подряд `apply` после Update: второй NoOp (свойство идемпотентности).
- Override детерминирован: два вызова генерации дают побайтово один файл.
- Обрыв посреди деплоя: повторный запуск завершает деплой, а не стартует новый.
- Стек с двумя сервисами: обновление одного не вызывает вызовов к другому.
